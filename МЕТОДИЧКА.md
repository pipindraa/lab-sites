# Лабораторная работа «Компьютерные сети»: развертывание веб-сайтов разными способами

**Цель:** развернуть 3 простых сайта разными технологиями на одном сервере Linux и описать процесс так, чтобы любой студент мог повторить за 20–30 минут.

**Что в папке `lab-sites`:**

| № | Папка | Тип | Технология | Порт локально |
|---|-------|-----|------------|---------------|
| 1 | `site-node` | Многостраничник + JSON API (не одностраничный) | Node.js 20 + Express | 3001 |
| 2 | `site-php` | Одностраничник-лендинг с формой | PHP 8 + php-fpm, чистый PHP без фреймворка | 3002 (`php -S`) / сокет php-fpm |
| 3 | `site-aspnet` | «Еще что-нибудь»: 2 страницы + JSON API | ASP.NET Core 10 Minimal API | 5001 (Kestrel) |

Схема на боевом сервере (один nginx на :80 разруливает всё):

```
Интернет → nginx :80 ─┬─ /         → http://127.0.0.1:3001/ (Node, сайт №1)
                       ├─ /php/     → php-fpm через сокет (PHP, сайт №2)
                       └─ /dotnet/  → http://127.0.0.1:5001/ (ASP.NET, сайт №3)
```

---

## Вариант А (основной): сервер преподавателя — Ubuntu 22.04/24.04 + nginx

Предполагается: дан IP сервера, пользователь `student` с sudo, интернет есть.

### 0. Подготовка (5 мин)

```bash
# на сервере
sudo apt update && sudo apt install -y nginx nodejs npm php-fpm php-cli git
# dotnet 10 для сайта №3:
# см. https://learn.microsoft.com/dotnet/install/linux — кратко:
sudo apt install -y dotnet-sdk-10.0
node -v; php -v; nginx -v; dotnet --version
```

### 1. Залить сайты на сервер

```bash
# с твоего ПК (замени IP):
scp -r lab-sites student@SERVER_IP:/home/student/
# или через git, если залил на GitHub:
# git clone <твой-репо> lab-sites
```

Разложить по каноничным путям:

```bash
sudo mkdir -p /var/www/site-php /opt/site-node /opt/site-aspnet
sudo cp -r ~/lab-sites/site-php/* /var/www/site-php/
sudo cp -r ~/lab-sites/site-node/* /opt/site-node/
sudo cp -r ~/lab-sites/site-aspnet/* /opt/site-aspnet/
sudo chown -R www-data:www-data /var/www/site-php
```

### 2. Запустить Node (3001) и ASP.NET (5001) как сервисы

Файлы `deploy/systemd/site-node.service` и `site-aspnet.service` из этого репо → скопировать:

```bash
cd ~/lab-sites/site-node && npm install --omit=dev
sudo cp ~/lab-sites/deploy/systemd/*.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now site-node site-aspnet
systemctl status site-node site-aspnet --no-pager
curl http://127.0.0.1:3001/api/info
curl http://127.0.0.1:5001/api/info
```

### 3. Настроить nginx (один файл на всё)

```bash
sudo cp ~/lab-sites/deploy/nginx/lab-sites.conf /etc/nginx/sites-available/lab-sites
sudo ln -sf /etc/nginx/sites-available/lab-sites /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
```

Проверка с ноутбука:

```
http://SERVER_IP/        — Node, многостраничник (сайт №1)
http://SERVER_IP/php/    — PHP, одностраничник (сайт №2)
http://SERVER_IP/dotnet/ — ASP.NET + API (сайт №3)
```

### 4. Типовые ошибки

| Симптом | Причина → лечение |
|---------|-------------------|
| 502 Bad Gateway на `/` | Node не запущен → `journalctl -u site-node -e` |
| 502 на /dotnet/ | Kestrel не слушает 5001 → `systemctl status site-aspnet` |
| 404 на /php/ | неверный `alias` / нет php-fpm сокета → `ls /run/php/*.sock`, `nginx -t` |
| Стили не грузятся | пути `/node/style.css` больше нет — Node теперь на `/`, смотри `lab-sites.conf` |

### 5. Что показать преподавателю

1. Все 3 URL открываются.
2. `curl http://SERVER_IP/api/info` и `http://SERVER_IP/dotnet/api/info` возвращают JSON.
3. Формы на PHP (одностраничник) и на Node принимают POST и показывают «Спасибо».
4. `sudo nginx -T | head -60` — конфиг, `systemctl status` — сервисы.

## Вариант Б (запасной): бесплатный хостинг без своего сервера

Если сервер преподавателя недоступен, каждый сайт поднимается бесплатно за 10 минут.
Нужны 2 регистрации (обе бесплатные, карта не нужна):

1. **GitHub** — хранить код.
2. **Render.com** — хостить все 3 сайта (через регистрацию «Sign up with GitHub»).

| Сайт | Куда | Как |
|------|------|-----|
| №1 Node | **Render.com (Free, native Node)** | New → Web Service → репо, Root: `site-node`, Build: `npm install`, Start: `npm start`. Засыпает без трафика, для демо хватает |
| №2 PHP | **Render.com (Free, Docker)** | Тот же репо, Root: `site-php`, Dockerfile уже лежит в папке |
| №3 ASP.NET | **Render.com (Free, Docker)** | Root: `site-aspnet`, Dockerfile уже лежит в папке |

Файл `render.yaml` в корне — Blueprint: можно поднять всё одной кнопкой (New → Blueprint → выбрать репо).

## Локальный прогон (для репетиции, без сервера)

```bash
# №1 (многостраничник):
cd site-node && npm install && npm start      # → http://localhost:3001
# №2 (одностраничник):
cd site-php && php -S localhost:3002          # → http://localhost:3002
# №3 (API):
cd site-aspnet && dotnet run                   # → http://localhost:5001 (порт из лога)
```

## Скриншоты для отчёта

Приложи: 3 открытых сайта + 2 JSON (`/api/info`, `/dotnet/api/info`) + вывод `nginx -T`.
Этого достаточно для зачёта по «развертыванию».
